# Ads and privacy

Legend Arrow is for a mixed audience (children and adults). There is no account, no age screen and no backend. **Every player gets the restrictive child/unknown treatment.** Ads only add optional hints; the whole campaign is earnable offline without ads.

## Formats
| Format | When | Audience |
|---|---|---|
| Rewarded ("Watch ad · Get 1 hint") | Only after the player taps it in the hint sheet, once the 3 free hints for that puzzle are used. The reward is stated before showing. | All (child-directed, under-age, G-rated requests) |
| Interstitial | Only between levels after a completed level, never on first launch, tutorial, failure, Back, resume or during an awakening; ≥ 5 completed non-tutorial levels and ≥ 180 s since any full-screen ad. | **Disabled** for child/unknown (i.e. everyone in v1) |
| Banner, app-open | Never | — |

Limits live in `RemoteConfig` (hard minimums 5 levels / 180 s). Overrides can only reduce ad pressure or switch formats off, never on; there is no server in v1.

## Code map
- `scripts/services/ad_service.gd` — rewarded state machine `IDLE → LOADING → READY → SHOWING → REWARDED | DISMISSED → IDLE`, `FAILED` with a 5 s retry cooldown (no automatic retry loop). Hints are granted only from the SDK's earned-reward callback, once per presentation id, persisted immediately (`Progression.grant_ad_hint`, receipt in the save). Duplicate, late, unknown and post-restart callbacks are harmless. Full-screen start/end mute and restore game audio.
- `scripts/services/consent_service.gd` — one UMP consent request per launch; refusal, errors and offline only disable ads.
- `scripts/services/ad_config.gd` — Google's official **test IDs** for debug builds and CI. Release builds read `ads_release.json` (owner-supplied, git-ignored) and refuse to request ads if IDs are missing, are test IDs, the UMP message is not configured, or the audience is invalid.
- `scripts/services/mock_ad_provider.gd` — scriptable fake SDK (fill, no fill, offline, fail to show, early dismiss, duplicate and late rewards). Used on desktop, in every test and in every E2E journey. The one exception is the emulator first-launch smoke (`cold_start_smoke`), which starts the real debug build: UMP and Google Mobile Ads initialise with Google's **test** IDs (a test ad may be preloaded); nothing is shown or clicked, and no live ad is ever requested.
- `android/plugins/legend_ads/` — Kotlin Godot plugin "LegendAds": UMP + Google Mobile Ads 24.4.0 / UMP 3.2.0. Sets `TAG_FOR_CHILD_DIRECTED_TREATMENT_TRUE`, `TAG_FOR_UNDER_AGE_OF_CONSENT_TRUE`, `MAX_AD_CONTENT_RATING_G` for child/unknown (enforced in `AdSettings.parse` even if the game sent other flags). SDK-independent logic in `core/` with JUnit tests.
- `addons/legend_ads/` — editor export plugin: adds the AAR, Maven dependencies, the AdMob app id meta-data and **removes `com.google.android.gms.permission.AD_ID`**.

## Permissions
`INTERNET`, `ACCESS_NETWORK_STATE` (ads only), `VIBRATE` (optional haptics). No location, camera, microphone, contacts, storage, notifications or advertising ID.

## Data
The game save holds progress, settings, hint counts and opaque ad presentation receipts (random ids generated by the game). It holds no advertising identifiers, consent strings, names, ages or tap streams. Local events (`EventLog`) stay on the device and are never uploaded in v1. The ads SDK collects its own data subject to consent and child-directed settings — the Data Safety inventory (M6) must list it from the actual SDK versions.

## Owner prerequisites before release
1. AdMob account: app + rewarded unit (+ interstitial unit, currently unused for this audience).
2. UMP/consent message configured in AdMob Privacy & messaging for applicable regions.
3. `ads_release.json` at the project root (not committed):
   ```json
   {"app_id": "ca-app-pub-XXXX~YYYY", "rewarded_unit": "ca-app-pub-XXXX/ZZZZ",
    "interstitial_unit": "ca-app-pub-XXXX/WWWW", "audience": "unknown", "consent_configured": true}
   ```
4. Play Console: target audience includes children → Families policy, Families-certified ad SDK settings, Data Safety form, hosted privacy policy.
